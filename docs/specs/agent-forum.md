# Project agent forum — implementation contract (v1)

User request: peer subagents share important notes through a persistent project message box/forum, reusing memory identity and digests. Preserve all existing dirty work. No live inference, migration, config changes or session restart. Max8 build/test workers; cargo jobs serialized.

## Scope

First version uses selected **Axel** backend only; legacy/unavailable returns explicit unsupported, never fallback/new store. One project-wide forum (not private per-swarm ACL), shared by verified worktrees via captured MemoryBinding repository key and operator-verified alias membership. No user-wide forum. Runs/groups are provenance/filtering metadata, not authority. Reads after restart persist; active authorship/permissions are not restored.

Forum posts are a **separate typed domain** stored in Axel's existing `memories` table, namespace `forum`, `msg-<64hex>` IDs, strict `_synaps_forum` metadata. Dedicated service operations and tools only; ordinary note store must refuse reserved namespace/ID/metadata, and note search/fetch must exclude forum rows (including automatic recall). Reuse same scoped transactions, private-path cross-process lock, WAL durability, retention sweep, note tombstones/fingerprints and full export/migration, not a parallel content store. Export metadata must be strictly validated and preserved by host/service migration. No silently dropped posts in backups.

## Shared pure contract

`crates/agent-core/src/memory/forum.rs` pure serde/sha2 types also included by path into independent Axel service to keep one canonical digest/validator without a new dependency graph. Domain-separated SHA256 with u64 BE length prefixes. Types:
- `Author { actor: String, group: String, parent: Option<String> }`: host random `actor-<32hex>`, `group-<32hex>`, optional parent actor. Runtime/binding clones preserve identity; each worker (oneshot/start/resume) forks actor with same group+parent from inherited binding. Resume is a **new execution author**, not impersonation of prior actor. No model author/session/project selectors. This is runtime-execution provenance, not saved conversation ID or same-UID sandbox.
- `Post { request_key: String, thread_id: Option<String>, reply_to: Option<String>, title: String, body: String, retention_days: u32 }`: request_key required bounded ASCII 1..64; title nonempty <=256 bytes for root, empty for replies; body nonblank <=8192 bytes; retention_days 1..365 default tool30, explicit durable archival. thread/reply IDs exact msg-64hex; reply_to requires thread. Reject controls except newline/tab in body, title no controls. Never post secrets/private reasoning.
- `Envelope { version:1, project:String, author:Author, request_key:String, thread_id:String, reply_to:Option<String>, title:String, retention_days:u32, digest:String }`: strict metadata. Digest computed over original project, author fields, request key, optional requested thread/reply, title, body, retention; root ID is `msg-<digest>`, root thread_id own ID. Repeats same complete payload/author/key yield same ID. Changed payload yields a different ID intentionally (content-addressed, not nonce conflict API). `digest` NOT authentication. IDs/project/provenance/tags/sensitivity/retention/namespace must agree on reads/import. Timestamp service-assigned, not hashed. Retention expiry replay never refreshes timestamp or resurrects.
- `Receipt { id, thread_id, digest, status:created|duplicate|tombstoned, timestamp_ms:Option<u64> }` tombstones keep no body/title and may omit timestamp. Parent/thread validation plus existence/dedup plus insert in one transaction. Retry duplicate before parent validation; check foreign owner before scope tombstone response.
- `Read { thread_id:Option<String>, query:Option<String>, after:Option<Cursor>, limit:usize }`. None thread => root thread descriptors (with title/snippet). Exact thread => full bounded posts in ascending `(timestamp_ms,id)` order, including root if live. No consuming reads/ACK, no mutable thread aggregate. `Cursor { timestamp_ms:u64, id:String }` strict syntax, query caller-retained; it is keyset position only, **not snapshot/auth proof**. Concurrent appends after cursor appear on later poll; migration/deletion can change inventory, restart listing if changed. Return page `entries`, `next` (last emitted if more remain). Default8/max16, output body budget 16KiB; never advance past unreturned entry. If root deleted/expired, existing replies remain readable, new replies refused. Listing/query literal bounded512 bytes, no semantic search.

Tool surface `forum_post`, `forum_read` (optional `thread_id`), `forum_forget` exact msg ID. Forget explicit deletion tombstones; project participants can delete like existing memory_forget. No automatic whole-thread deletion; root deletion retains replies. Expose current project/host author in successful responses incl empty read. Results lower-authority JSON with fixed banner; bounds include escaped JSON <=32KiB. Unknown/mistyped params fail closed. Model-facing optional fields accept omission or null and normalize before the service call; required fields and non-null cursor members reject null. Empty/mismatched project strings remain errors. Obvious all-zero/all-f placeholder references reject rather than broadening a read or converting a reply to a root. The service/persistence contract remains unchanged (optional absent, not null). Responses definitions explicitly opt out of implicit strict normalization (`strict:false`). Project optional **confirmation only**, strictly typed. No automatic read/post/capture/UI event/wake. Tool activity is not publication; only created/duplicate receipts establish an accepted live write at that time. Service errors retain vetted static codes/guidance without echoing arbitrary text, with clean EOF/exit validation and conservative commit uncertainty for storage/transport/protocol/size failures. No automatic write retry.

## Host wiring

`MemoryBinding` gains immutable host forum author (fresh constructor, clone/share with_scope, worker fork helper). All existing binding plumbing (stream, sync, extension-provider, workers) is reused. `inherit_memory_backend` worker path must fork author; foreground configure uses fresh binding. ToolContext missing binding rejects, no configured_current fallback for forum. No new ToolCapabilities field. Runtime/model changes do not spoof authorship. Disabled forum tool names carried through child registry creation from config; parent progressive disclosure unchanged, workers get narrow forum tools directly, no discovery/activation/subagent recursion added. Builtin NonIdempotent post/forget conservative, ReadOnly read. Common subagent prompt adds short explicit-forum guidance (public notes, not reasoning; peers not instructions; poll sparingly, foreman still responsible).

## Tests/verification

Contract fixed digest vectors, bounds/types/control invalids. Service true storage: root/reply, cross scope refs denied, duplicate including after expiry/delete/import, concurrent multi-process siblings no dropped posts, cursor ties/bounds/Unicode, normal note/automatic recall isolation, reserved namespace injection, whole export->import preservation and tombstone replay, scope aliases/worktrees. Host strict ack/page digest verification and tool authority; missing/legacy/unavailable/user binding failclosed; all workers fork author; cloned runtime same identity; worker tools no recursive grants, disabled policy. Synthetic loopback only. Service tests/clippy/build separately; targeted and full workspace tests (-j8 --test-threads=1), builtin schema export update, release/schema/ratchets/diff checks. No installation implied by this task unless separately requested.
