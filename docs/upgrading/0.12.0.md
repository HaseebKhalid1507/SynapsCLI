# Upgrading from 0.11.1 to 0.12.0

**After installing, reload the daemon:** `synaps daemon reload`, then
restart attached TUIs. A reload stops running subagents (`subagent_resume`
continues them), so let them finish first. Daemon protocol (v3) and
extension protocol (1) are unchanged.

## Memory is plain files only; Axel is an extension

0.12.0 removes everything in core that served the Axel memory backend:
the backend switch, the helper process (`synaps-axel-memory-service`), the
built-in project forum, built-in automatic capture and recall, the per-session
memory mode, the files-to-Axel migration and repository identity. Notes and
context archives are plain files under the base directory, always. Recall,
capture, search over everything and the forum come from the Axel extension.

**If your config has no `memory.*` lines, nothing changes for you.**

### If you used `memory.backend = axel`

A config that still has `memory.backend`, `memory.user_scope`,
`memory.axel.executable` or `memory.axel.brain` loads and starts as before,
with one warning per start. The session uses plain files. **Archives and
notes saved in the Axel brain are not read any more** until you move them:

1. Export them from the brain (read-only; the brain is not changed):
   `axel synaps-export --brain <brain.r8> --out <empty folder>`. The brain is
   the `memory.axel.brain` value, or `<base>/memory/axel/brain.r8`
   (`~/.synaps-cli/memory/axel/brain.r8`) when that line is absent. It writes,
   per project key, `<key>/archives.jsonl` and `<key>/notes.jsonl`, and a
   `manifest.json`.
2. Import each project into the plain-file stores, dry run first, filing it
   under the folder its chats ran in:
   `synaps memory import-archives --cwd <folder> --dry-run <key>/archives.jsonl`,
   then without `--dry-run`; the same with `import-notes` and
   `<key>/notes.jsonl`. `synaps memory project --cwd <folder>` prints a
   folder's key and where its memory lives; when that is the exported `<key>`,
   `--as-recorded` (keep the key each line names) does the same.
   `--project-key <key>` files every line under a key you give. A line that is
   already in the store is counted as `already_present` and not written again,
   so a second run is safe.
3. Install the Axel extension (plugin directory `axel`) for recall, capture,
   search and the forum.
4. Remove the `memory.backend`, `memory.user_scope` and `memory.axel.*`
   lines.

User-wide notes (`scope = user`) have no home in Synaps any more; the ones in
an Axel brain stay there.

## The plugin sidecar system is gone

A plugin can run its own process one way: as an extension. The second way,
the "sidecar" (`provides.sidecar` in `plugin.json`, built for voice
dictation), is removed with no replacement. Gone with it: `/sidecar`, the
plugin-claimed `/<word> toggle|status` commands, the header pill, the
`/settings` → Sidecar page, the per-plugin "Toggle key" row, the F8 key core
always bound, the `sidecar.spawn_args` extension call and the
`provides.sidecar.setup` build-script slot.

- **A `plugin.json` with `provides.sidecar` still loads.** The block is
  ignored and the log says so once per load (``plugin '<name>':
  `provides.sidecar` is ignored; sidecars are no longer supported (removed
  in 0.12.0)``). The
  plugin's extension, commands, keybinds and settings work as before.
- **`/voice toggle` and `/voice status`** (or whatever word a plugin
  claimed) now go to the plugin's own `voice` command, like any other
  subcommand; a plugin without such a command gets the usual "unknown
  command". `local-voice` 0.1.0 has a `voice` command, and it does not
  know `toggle` or `status`: it answers `unknown subcommand: toggle`. Its
  C-Space keybind sends `/voice toggle`, so every C-Space press shows that
  error until the plugin is updated, the keybind is removed from its
  `plugin.json`, or the plugin is uninstalled. Dictation itself does not work any
  more: disable or uninstall `local-voice` (`/plugins`) until a version
  built on extensions exists.
- **A build script only under `provides.sidecar.setup` no longer runs.**
  Declare it as `extension.setup`. For `local-voice` this means a fresh
  install or an update no longer runs `scripts/setup.sh`, so
  `bin/synaps-voice-plugin` is not built and the plugin's extension fails
  to load. The load error's hint no longer points at the script either,
  because the hint only reads `extension.setup`.
- **Old toggle-key entries are ignored silently.** Keys of the form
  `plugins.<plugin>.<category>._lifecycle_toggle_key` (written by the
  0.11 toggle-key migration) stay in the config file; nothing reads them
  and nothing warns. Delete them if you like.
- **Theme files** that set `sidecar.pill` load; the key is ignored like any
  unknown key.
- **`/sidecar`** is an unknown command.

## Removed config keys

Each still loads, with a warning, and does nothing:

| Keys | Warning says |
|---|---|
| `memory.backend`, `memory.user_scope`, `memory.axel.executable`, `memory.axel.brain` | plain files are the only memory storage; move once (above), then remove |
| `memory.default_mode`, `memory.default_mode_confirmed`, `memory.recall_*`, `memory.capture_*`, `memory.auto_consolidate`, `memory.local_embeddings`, `memory.gliner` | built-in automatic memory was removed; an extension provides it through hooks |
| `sidecar_toggle_key` | the plugin sidecar system was removed, so core binds no toggle key; plugin keybinds and `keybinds` still work |

`/settings` has no Memory or Sidecar page and refuses to write these keys.

## Removed commands and tools

| Gone | Instead |
|---|---|
| `/memory`, the `memory_context` tool | an extension (Axel) does capture and recall; `/memory` prints one line saying so |
| `/sidecar [plugin] toggle\|status`, plugin-claimed `/<word> toggle\|status` | nothing (sidecars are gone); `/<word> …` reaches the plugin's own command if it has one |
| `forum_post`, `forum_read`, `forum_forget` | the Axel extension's `axel:forum_post`, `axel:forum_read`, `axel:forum_forget` |
| `synaps retention memory-scope`, `upgrade-memory`, `migrate-memory` | `synaps memory import-archives`, `import-notes`, `project` |
| `synaps retention forget` domain `history` (it existed only for the Axel backend) | `memory_forget` with the archive's `ctx-` id |

The four memory tools (`memory_search`, `memory_fetch`, `memory_store`,
`memory_forget`) lose their `scope` parameter. `scope: "repository"` is still
accepted and ignored; any other value is refused with `memory: user-wide
notes are not available; omit scope`. `project` is unchanged.

## Behaviour changes

- **Workers are no longer told about a forum by core.** Put what workers
  should know about the Axel forum in `<base>/subagent-preamble.md`; it is
  still prepended to every worker prompt.
- **A resumed chat whose archive is not in its folder's store goes on at
  window 1** instead of refusing to continue; `/context status` says which
  archive is missing and why (usually: opened from another folder).
- **Extension and MCP tools named like the memory tools run like any other
  tool**; nothing refuses them any more.
- **`tool.call` still carries `caller`** (the run's author, its group and
  its parent), unchanged.
- An extension manifest that declares `deferred.context_providers` or asks for
  `context_providers.register` loads as its other parts say; the declaration
  grants nothing.
